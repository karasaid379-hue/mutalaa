## Amaç
Editör kipindeki ASP.NET Core 10 Minimal API kurulur: ASP.NET Core Identity ile oturum ve roller, salt okunur kaynak kaydı uçları ve birim uçları, tek `review` tablosu üzerinden inceleme kuyrukları ve ikinci onay, yayın talebi uçları, RFC 9457 hata modeli ve depoya giren OpenAPI belgesi. Editör paneli (A15) bu belgeden üretilen istemciyle çalışır; içerik hattının adayları bu uçlarla onaylanır. Aşama tedarikle başlar: API'nin kullandığı hazır kitaplıklar (OpenAPI, Scalar, Serilog, sağlık denetimi, test araçları) sürümleri sabitlenerek alınır; yeniden yazılmaz.

### A14.0 · Tedarik doğrulaması ve indirme
- `arastirmaci` `## Tedarik` tablosundaki adreslerin açıldığını ve sürümlerin güncel olduğunu doğrular. Kitaplığın varlığı ve son kararlı sürümü NuGet kayıt dizininden okunur (`https://api.nuget.org/v3-flatcontainer/<kimlik küçük harfle>/index.json`); `www.nuget.org/packages/...` sayfaları GET isteğine 200, HEAD isteğine 404 verir. Learn ve Scalar adresleri açılır, güncelleme tarihleri tablodakilerle karşılaştırılır. Açılmayan adresin ya da kayıtta bulunmayan sürümün yerine tablodaki yedek aday kullanılır ve tablo güncellenir.
- Bu aşama içerik kaynağı almaz: `data/gelen/` altına dosya inmez, `pipeline/sources/` altına kayıt açılmaz. Alınan yapılar NuGet kitaplıklarıdır; paket dosyalarını `dotnet restore` indirir. Sürümler `server/Directory.Packages.props` içinde sabitlenir (A14.2); `packages.lock.json` her paketin içerik özetini (`contentHash`) kaydeder.
- Sürümü paket kaydından doğrula: `dotnet list server/Mutalaa.slnx package` istenen ve çözümlenen sürümü, `--outdated` bayrağı kayıttaki son kararlı sürümü gösterir. Tablo, `Directory.Packages.props` ve komut çıktısı aynı sürümleri vermelidir.
- `Microsoft.AspNetCore.OpenApi` 10.0.14, `Microsoft.OpenApi` paketini `[2.12.2, 3.0.0)` aralığıyla getirir; kayıttaki son kararlı `Microsoft.OpenApi` 3.x'tir. Doğrudan `Microsoft.OpenApi` başvurusu eklenmez, çünkü sürüm aralığı çakışır.

### A14.1 · Doğrulamalar
- `arastirmaci` aşağıdaki maddeleri resmî kaynakla ve çalışan kodla doğrular. Bunlar Backend API §2, §3 ve §6'da "Doğrulanacak" diye işaretlidir. Tedarik araştırması (1 Kasım 2026) belgeleri okudu; kod düzeyindeki sınama bu adımdadır:
  - **Minimal API doğrulaması (`AddValidation()`).** Kaynak: [Validation in ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/validation?view=aspnetcore-10.0) (güncelleme 31 Ekim 2026). Kaynak üretici yalnız `AddValidation` çağrılan derlemeyi kapsar; bu yüzden istek tipleri `Mutalaa.Api` içinde tanımlanır, `Mutalaa.Domain` pakete bağımlı olmaz. .NET 10'da null olabilen değer türü parametreler doğrulanmaz ([dotnet/aspnetcore #67033](https://github.com/dotnet/aspnetcore/issues/67033)); bilinmeyen JSON alanını reddetmek için `UnmappedMemberHandling = Disallow` gerekir. Kod sınaması: zorunlu alanı eksik istek 400 `HttpValidationProblemDetails` döner. **Sonuç (10 Kasım 2026):** sınandı, 400 `HttpValidationProblemDetails` dönüyor (alan adları snake_case'e çevrilir); [Backend API](../../02-mimari/05-backend-api.md) §6 "Çözüldü" olarak işaretlendi.
  - **Derlemede OpenAPI belgesi.** Kaynak: [Generate OpenAPI documents](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/openapi/aspnetcore-openapi?view=aspnetcore-10.0) (güncelleme 29 Ekim 2026). `Microsoft.Extensions.ApiDescription.Server` belgeyi derlemede üretir; dizin `OpenApiDocumentsDirectory`, dosya adı ve sürüm `OpenApiGenerateDocumentsOptions` ile (`--file-name`, `--openapi-version`) verilir. Üretim giriş noktasını `GetDocument.Insider` adıyla çalıştırır; veritabanı kodu `Assembly.GetEntryAssembly()?.GetName().Name != "GetDocument.Insider"` denetimiyle atlanır. .NET 10 varsayılanı OpenAPI 3.1'dir (.NET 11'de 3.2): `OpenApiVersion` açıkça `OpenApi3_1` yazılır. Kod sınaması: `dotnet build -c Release` veritabanı olmadan `openapi/v1.json` üretir; `--openapi-version` seçeneği 10.0.14 ile çalışmazsa çalışma zamanı ayarı yeterlidir. **Sonuç (10 Kasım 2026):** `--openapi-version OpenApi3_1` 10.0.14'te çalışıyor (`OpenApiGenerateDocumentsOptions` = `--file-name v1 --openapi-version OpenApi3_1`); belge veritabanı olmadan üretiliyor; `OpenApiGenerateDocumentsOnBuild` yalnız `Release` yapılandırmasında açık; üretilen belge `Production`, `Development` ve `Staging` ortamlarında bayt bayt aynı (`servers` boşaltılır); `RunWorkingDirectory` csproj'ta depo köküne verildi. Backend API §6 "Çözüldü" olarak işaretlendi.
  - **Scalar uç adı.** Kaynak: Scalar belgesi (`documentation/integrations/aspnetcore/integration.md`, commit `66ba1d76`). `app.MapScalarApiReference()` varsayılan yolu `/scalar`, varsayılan belge adı `v1`'dir. Backend API §6'daki `/scalar/v1` yolu çalışan API ile doğrulanır; farklıysa Backend API düzeltilir. **Sonuç (10 Kasım 2026):** `/scalar/v1` doğru yoldur; Backend API değişmedi.
  - **Çerezde 401 ve 403.** Kaynak: [Cookie login redirects are disabled for known API endpoints](https://learn.microsoft.com/en-us/aspnet/core/breaking-changes/10/cookie-authentication-api-endpoints?view=aspnetcore-10.0) (güncelleme 29 Ekim 2026; .NET 10 Preview 7'den beri). JSON okuyan ya da yazan Minimal API uçları ve `TypedResults` kullanan uçlar yönlendirme yerine 401/403 döner; yanıtta `Location` başlığı kalır, yalnız durum kodu değişir. JSON yazmayan uç (sayfa görseli) kendiliğinden tanınmaz: `DisableCookieRedirect()` eklenir. Kod sınaması: oturumsuz JSON ucu ve oturumsuz görsel ucu 401 döner. **Sonuç (10 Kasım 2026):** Learn'ün beklentisi tutmadı. .NET 10'da `IResult` dönen düz Minimal API uçlarında çerez yönlendirmesi kapanmıyor: yanıt 302 ve `Location` ile geliyor; `TypedResults` ya da JSON gövde de `Location` başlığını kaldırmıyor. Çözüm: `AddIdentityCookies`'in `Events` nesnesinde `OnRedirectToLogin` yalnız 401, `OnRedirectToAccessDenied` yalnız 403 yazacak biçimde ezildi (olaylar bütün uçlar için geçerlidir; `DisableCookieRedirect()` gerekmez); gövdeyi `UseStatusCodePages` ProblemDetails ile doldurur. Oturumsuz JSON ucu ve oturumsuz görsel ucu testle 401 döner ve `Location` taşımaz. Backend API §6 buna göre düzeltildi.
  - **`kalite-kapisi` hata kodu.** Backend API §6 kalite kapısına takılan yayın için 422 `kalite-kapisi` kodunu yazar; kod ve durum, yayın uçlarıyla birlikte sınanır. Değişirse Backend API ile A15 aynı değişiklikte eşitlenir. **Sonuç (10 Kasım 2026):** kod ve durum değişmedi; önizleme 422 `kalite-kapisi` ve `kapi_raporu` uzantısıyla döner (testle kanıtlandı: P-01 ihlali).
- Npgsql enum eşlemesi, `xmin` (`IsRowVersion()`) ve `EFCore.NamingConventions` desteği A07'de çözüldü (27 Ekim 2026; [Editoryal veritabanı](../../03-veri/02-editoryal-veritabani.md) §12); burada yeniden doğrulanmaz.
- Kararlar `/karar` ile, çözülen maddeler `/belge-esitle` ile işlenir.
- **Bitti sayılır:** her madde kaynak bağlantısıyla raporlu.

### A14.3 · Kaynak ve birim uçları
- `GET /api/v1/sources`, `/sources/{slug}`: kaynak kaydının alanları (`slug`, `tur`, `baslik`, `yazar`, `surum`, `provider`, `kaynak_url`, `alinma_tarihi`, `dosya_sha256`, `baski_bilgisi`, `atif_metni`, `atif_url`, `notice_text`, `notlar`, `created_at`, `updated_at`) ve birim sayısı. Uçlar salt okunurdur: kaynak kaydını yazan uç yoktur; kayıt `pipeline/sources/{slug}.toml` dosyasından içerik hattıyla gelir. JSON alanları sütun adlarıyla aynıdır (snake_case); enum değerleri veritabanı etiketleridir.
- `GET /api/v1/units?source=&prefix=&q=&cursor=&limit=`: `q` A05'in C# normalizasyonundan geçer (`TurkishWide` ve `Arabic` anahtarları) ve `tr_wide` ile `ar_norm` sütunlarında alt dizgi olarak aranır (PostgreSQL'in Türkçe gövdeleyicisi bizimkinden farklı olduğu için; başarım ölçümü A20 ve A31'e bırakıldı); `q` en çok 1.024 kod noktasıdır (aşarsa 400); `prefix` çapa önekidir (`LIKE` kaçışı yapılır); sıralama `(source_id, ord, id)` anahtar kümesidir; imleçli sayfalama, en çok 200, yanıt `{ "items": [...], "next_cursor": "..." }`.
- `GET /units/{anchor}`: çapa `AnchorRef` ile doğrulanır; geçersizse 400 `capa-gecersiz` (`capa_hata_kodu` ek alanı hata kodunu verir); kelime, `@` aralığı, cümle, âyet aralığı ve konu çapası birim olmadığı için aynı kodla 400 alır. Ayrıntı `duzeltilebilir` alanını ve `ETag` (`"{xmin}"`) başlığını taşır.
- `POST /units/{anchor}/corrections`: yalnız kendi ürettiğimiz metinde; önerilen metin NFC'ye çevrilir ve `review` satırı olur. Hazır kaynak metninde (Tanzil) 422 `degistirilemez-metin`. **Karar ([K-48](../../00-ozet/02-karar-defteri.md#k-48--editör-api-kuralları-inceleme-kararı-ikinci-onay-eşzamanlılık-yayın-talebi-ve-sayfa-görseli) madde 5):** değişmez metin `unit.kind = 'ayet'` ya da `source.tur = 'kuran_metni'` olandır; düzeltme ve metin onayı ikisinde de 422 `degistirilemez-metin` alır. Bayt bayt alınan öteki hazır metinler (ör. hazır Arapça hadis) bu kuralın dışındadır; konu [BÇ-52](../07-belge-celiskileri.md) olarak A19'a yazıldı. Düzeltme önerisi kayıt anında ilk kayıt kuralından geçer (NFC); "değişiklik yok" denetimi bundan sonra yapılır (400). Başarıda 201 ve `Location` (`/api/v1/reviews/{id}`) döner; aynı birim için açık bir metin incelemesi varsa 409 `cakisma`.
- Not (EF sınırı, [Editoryal veritabanı](../../03-veri/02-editoryal-veritabani.md) §12): `prefix` ve çapa aralığı sorguları dönüştürülmüş çapa sütunlarında LINQ ile `LIKE` ya da aralık işlecine çevrilmez; ham SQL ya da `AsNoTracking()` ile projeksiyon kullanılır. `unit` okumaları `tsv_tr` ve `tsv_ar` gölge sütunlarını da seçeceği için projeksiyon yapılır.
- **Bitti sayılır:** uç testleri yeşil; kaynak uçlarında `GET` dışındaki yöntemler 405 dönüyor; Tanzil birimine düzeltme 422 dönüyor.

### A14.4 · İnceleme kuyrukları ve ikinci onay
- `GET /api/v1/reviews?hedef_tablo=&alan=&durum=acik&cursor=&limit=`, `GET /reviews/{id}` (`onceki`, `onerilen`, `duzenlenen`, `yz_modeli`, `yz_kaydi`, `guven`, `ikinci_*`, `xmin`; ayrıntıda `hedef` anlık görüntüsü ve `ETag`), `GET /reviews/stats` (`{kuyruklar: [{hedef_tablo, alan, acik}], toplam_acik}`). Sıralama `(created_at, id)`'dir; kuyruğa özgü sıralar A17 ve A18'e kalır.
- `POST /reviews/{id}/decision` (`{karar: onaylandi|reddedildi, duzenlenen?: {metin}, gerekce}`) ve `POST /reviews/decisions` (toplu: `{kararlar: [{id, xmin, karar, duzenlenen?, gerekce}]}`, 1 ile 100 öğe, tek işlemde ya hepsi ya hiçbiri). Eşzamanlılık ([K-48](../../00-ozet/02-karar-defteri.md#k-48--editör-api-kuralları-inceleme-kararı-ikinci-onay-eşzamanlılık-yayın-talebi-ve-sayfa-görseli) madde 6): ETag `"{xmin}"`'dir; tekil karar `If-Match` ister (yok: 428 `surum-gerekli`; `*`, `W/` ya da liste: 400 `dogrulama`; tutmayan: 412 `surum-uyusmazligi`); toplu karar `If-Match` taşımaz, sürüm her öğenin `xmin` alanındadır ve 412 yanıtı tutmayan kimliklerin tam listesini `kimlikler` uzantısında verir. Yazım izlenen güncellemedir (`RowVersion.Expect`); `ExecuteUpdateAsync` kullanılmaz.
- Karar satırı ve denetim izi (K-48 madde 1): onayda `durum = onaylandi`, `eylem = onayla` (değer düzenlendiyse `duzenle_onayla`); retde `durum = reddedildi`, `eylem = reddet` ve hedef değişmez. `gerekce` zorunludur (en çok 2.000 karakter). Karar verilmiş kayda yeni karar 409 `durum-gecisi-gecersiz` alır. Denetim izi için tek göç (`AddReviewAuditColumns`) `duzenlenen`, `ikinci_incelendi_at` ve `ikinci_gerekce` sütunlarını ekler; `onerilen` özgün öneri olarak kalır. Kendi `status` alanı olan tablolarda onay `onayli`, ret `red` yazar (hedef `aday` değilse 409). Birim metni onayında `metin_durumu = 'onayli'` olur; `content_hash`, `rev`, `tr_narrow`, `tr_wide` ve `ar_norm` yenilenir, `tr_stem` NULL olur ([BÇ-53](../07-belge-celiskileri.md), A16).
- A14'te uygulanan hedefler (K-48 madde 2 ve 3): `surah_alias`, `xref`, `lemma`, `lemma_gloss`, `quran_word_fix` ve `unit` + `metin`. `tr_root_index`, `tr_form`, anlam düzenleme, `new_value` düzenleme, bağlantıda hedef, aralık ya da tür değişimi, uzmana gönderme ve etimolojik işaret A17 ve A18'dedir; A14 bunlara 422 `inceleme-desteklenmiyor` döner.
- İkinci onay (K-48 madde 4): yalnız `unit` + `metin` kayıtlarında ve `unit.kind` `meal` ya da `tefsir` iken. İlk onay `inceleyen`, `incelendi_at` ve `gerekce` alanlarını doldurur, kayıt `acik` kalır; `taslak` birim `incelemede` olur, `onayli` birim ikinci onaya kadar eski metnini ve `onayli` durumunu korur (K-47). Farklı bir editörün onayı değeri uygular ve `ikinci_inceleyen`, `ikinci_incelendi_at`, `ikinci_gerekce` alanlarını doldurur; ikinci onay değeri değiştiremez (422 `inceleme-desteklenmiyor`), aynı kişinin ikinci onayı 409 `durum-gecisi-gecersiz` alır. Ret her aşamada verilebilir (`incelemede` birim `taslak`a döner). Dört göz: `koken = editor` kayıtta öneren kendi önerisini onaylayamaz (409).
- `oneren` ve `inceleyen` alanlarına Identity kullanıcı adı yazılır. Değişmez metin için metin onayı 422 `degistirilemez-metin` alır. `yz_modeli` dolu kayıt yanıtta `dogrulanmamis: true` taşır (K-25); ayrıntı `dogrulanmis` alanını hedefin durumundan türetir ([Editoryal veritabanı](../../03-veri/02-editoryal-veritabani.md) §8 notu, K-37). Liste öğeleri `ikinci_onay_bekliyor` alanını da verir.
- **OCR sayfa görseli (karar: K-48 madde 8).** `GET /api/v1/scans/{baski}/{sayfa}` (editor): `baski` `^[a-z0-9-]{1,64}$`, `sayfa` `^c[0-9]{2}-s[0-9]{4}$` desenine uyar; dosya `{RawDir}/{baski}/` altındaki bütün `YYYY-MM-DD` klasörlerinde yeniden eskiye `{sayfa}.{tif,tiff,png,jpg,jpeg}` olarak aranır ve olduğu gibi akıtılır; çözülen yol `RawDir` dışına çıkamaz; oturumsuz istek 401 ProblemDetails alır. Uç JSON yazmadığı için ayrı bir `DisableCookieRedirect()` gerekmez: çerez olayları bütün uçlarda 401/403 yazar (A14.1). TIFF gösterimi A15'in işidir; birimden görsele eşleme (`attrs` alan adları) A16'da kesinleşir.
- **Bitti sayılır:** karar, toplu karar ve ikinci onay testleri yeşil.

### A14.5 · Yayın uçları
- `POST /api/v1/releases` (admin): `{derleme, paketler?, notlar?}` → 202, `Location` (`/api/v1/releases/{id}`), `{id, surum, derleme, durum, talep}` ve `durum: hazirlaniyor` (`not` PostgreSQL'de ayrılmış sözcük olduğu için alan `notlar`dır; [K-46](../../00-ozet/02-karar-defteri.md#k-46--yayın-kaydı-içerik-özetleri-ve-fikstürler) madde 2). Kayıt `talep = yayin`, `paketler` ve `notlar` ile açılır. Sürüm istekte yoktur: `ReleaseVersion.Next` (Domain, A13) atar. `paketler` `PackCatalog.Default` ile doğrulanır; bilinmeyen paket 400 `dogrulama` alır.
- Süren yayın ([K-48](../../00-ozet/02-karar-defteri.md#k-48--editör-api-kuralları-inceleme-kararı-ikinci-onay-eşzamanlılık-yayın-talebi-ve-sayfa-görseli) madde 7): aynı derleme türünde açık (`hazirlaniyor` ya da `dogrulandi`) satır varken yeni talep, terfi ya da geri alma 409 `yayin-suruyor` alır; yanıtın `yayin` uzantısı açık satırı gösterir (`{id, surum, derleme, durum, talep}`). Denetim `ReleaseRepository.CreateAsync(..., requireNoOpen: true)` içinde danışma kilidiyle yapılır (Backend API §10.1).
- `GET /releases?derleme=&cursor=&limit=`, `/releases/{id:int}`: liste özet verir (`id` azalan); ayrıntı `kapi_raporu`, `ozetler`, `manifest`, `notlar`, `data_version`, `xmin` ve `ETag` taşır.
- `POST /releases/preview` (admin): `{derleme, paketler?}`; paket üretmeden kapı raporu. Kalite kapısının planlama aşaması `GatePlanner` (`Mutalaa.Infrastructure/Releases`) Yayınlayıcıyla ortak koddur; önizleme paket birleştirmeyi atlar (`SkipAssembly`) ve P-14 çalıştırmaz (P-14 yalnız terfidedir). Geçerse 200 `{derleme, kapi_raporu, uyarilar}`; kapıya takılan derleme 422 `kalite-kapisi` ve `kapi_raporu` uzantısıyla döner. Önceki yayının manifesti yoksa ya da okunamıyorsa 422 `onceki-yayin-bozuk`; önceki paketi okuyamazsa (depoda yok ya da özeti uyuşmuyor) 503 `depo-erisilemiyor`; başka bir önizleme sürüyorsa 409 `cakisma`. Önceki paketler `HttpPreviousPackResolver` ile yerel `data/packs`, `.tmp/api` önbelleği ve manifestteki herkese açık `url` sırasıyla çözülür (sha256 denetimli, 60 saniye zaman aşımı).
- `POST /releases/{id:int}/promote` ve `/rollback` (admin): gövde `{notlar?}` (hiç verilmeyebilir) → 202, `Location`, `{id, surum, derleme, durum, talep}`; işi Yayınlayıcı `watch` yapar; `public` terfisi yalnız kullanıcı kararıyla çalışır (Backend API §10.6). Talep `release` kaydında taşınır ([K-46](../../00-ozet/02-karar-defteri.md#k-46--yayın-kaydı-içerik-özetleri-ve-fikstürler) madde 2): yeni satır `talep = terfi` ya da `geri_alma` ve `kaynak_release_id` taşır.
  - **Terfi:** kaynak `yayinlandi` durumundaki `internal` yayındır (aksi 409 `durum-gecisi-gecersiz`); yeni satır `public` derleme türünde ve kaynağın sürümüyle açılır; aynı sürümle başarısız olmayan `public` satır varsa 409 `cakisma`.
  - **Geri alma:** hedef aynı derleme türünün `yayinlandi` ya da `geri_cekildi` yayınıdır; güncel yayına geri alma 409 `durum-gecisi-gecersiz`; yeni satır yeni sürüm alır (`ReleaseVersion.Next`) ve `kaynak_release_id` hedefi gösterir.
  - Bilinmeyen yayın kimliği 404 `bulunamadi`.
  - `data_version` Yayınlayıcının biçimidir (`DataVersions`); `olusturan` Identity kullanıcı adıdır.
- API yalnız `release` satırı açar; `Mutalaa.Api` ile `Mutalaa.Publisher` birbirine bağlanmaz. Alanlar A13'te eklendi (EF göçü).
- **Bitti sayılır:** 202, 409 ve yetki testleri yeşil.

## Dikkat
- Çerez kimlik doğrulaması .NET 10'da `IResult` dönen düz Minimal API uçlarında yönlendirmeyi kendiliğinden kapatmadı (A14.1 sınaması: 302 ve `Location`; JSON gövde ya da `TypedResults` kullanılsa da `Location` kalır). Bu yüzden `AddIdentityCookies`'in `Events` nesnesinde `OnRedirectToLogin` yalnız 401, `OnRedirectToAccessDenied` yalnız 403 yazacak biçimde ezildi (nesne yerinde değiştirilir, yenisi atanmaz: `OnValidatePrincipal` güvenlik damgası denetimi korunur). 401 ve 403 gövdesini `UseStatusCodePages` ProblemDetails ile doldurur ve testle kanıtlanır; `DisableCookieRedirect()` gerekmedi.
- Kültür: CA1304, CA1305, CA1307, CA1309, CA1310 ve CA1311 hata düzeyindedir; Türkçe küçük harf açık eşlemeyle yapılır ([Backend API](../../02-mimari/05-backend-api.md) §9).
- API açılışında otomatik göç yoktur. Her değişiklik en çok bir göç ekler; uygulanmış göç değiştirilmez (`ef-goc`).
- Hazır kaynak metni (Tanzil) hiçbir uçta değişmez; NFC yalnız kendi ürettiğimiz metne ilk kayıtta uygulanır.
